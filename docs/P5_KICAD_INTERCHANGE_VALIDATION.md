# P5 KiCad interchange validation

**Status: a strict RC source-to-native-template build passes KiCad checks; general-purpose source-to-KiCad board generation is not integrated.**

## Validated native RC handoff

On 2026-11-08, a clean native project was added at `integrations/tscircuit-rc/kicad/`. It uses the standard KiCad 10 symbol and footprint libraries through portable `${KICAD10_SYMBOL_DIR}` and `${KICAD10_FOOTPRINT_DIR}` paths. The project now acts as a reviewed template: each validation run rebuilds the tscircuit Circuit JSON/SPICE manifest from `design.json`, checks the exact RC source component set and pin topology, then copies the five KiCad project/library-table files and substitutes R1/C1 values in the schematic symbols and board footprints. The generated project is written under `build/tscircuit-rc/kicad-generated/`; the checked-in template remains unchanged. This deliberately supports only the fixed RC topology. It does not generate symbol selection, footprint choice, test-point topology, geometry, or routing from Circuit JSON.

The repeatable command is `npm run kicad:validate` from `integrations/tscircuit-rc/`. It runs in the digest-pinned KiCad 10.0.8 container, rebuilds the tscircuit Circuit JSON and SPICE manifest using the values currently in `design.json`, generates the native project from the reviewed template, verifies generated KiCad values and footprints against the source design and BOM, exports the KiCad netlist, and requires clean ERC, board DRC, and schematic/PCB parity. The current validation reported ERC 0, DRC 0, unconnected items 0, and parity issues 0. The exported KiCad nets are `/in` (R1:1, TP1:1), `/out` (R1:2, C1:1, TP2:1), and `GND` (C1:2, TP3:1); the source SPICE manifest maps the same series RC topology to its input, output, and ground nodes.

`EDASTACK_KICAD_TEMPLATE_DIR` can select another reviewed template, `EDASTACK_KICAD_PROJECT_DIR` selects the generated project output directory, and `EDASTACK_KICAD_VALIDATION_DIR` selects the validation-report directory. Each path must stay inside the repository workspace, and the template/output directories must not overlap. `npm test` covers source-value propagation, template integrity, exact component set and topology, BOM/footprint mapping, and manufacturing-output checks. Both the test suite and `npm run kicad:validate` run in the real-ngspice CI job and their `build/` evidence is uploaded when the job finishes.

The board is a 14 × 8 mm, two-copper-layer passive fixture with one 0603 resistor, one 0603 capacitor, and three 1.5 mm test pads. The input test pad was moved clear of the resistor courtyard and its reference text was moved off the pad outline. KiCad's board statistics report a 0.2000 mm minimum track width and a 0.4887 mm minimum track clearance for this revision. The board stores its drill/place origin at its lower-left corner (93, 104 mm); this keeps assembly coordinates positive and aligns the exported Gerbers to a 14 × 8 mm origin-relative edge outline. The generated container preview shows board geometry and pads, but does not show resistor/capacitor bodies.

The validator also regenerates a local manufacturing-output set under `build/tscircuit-rc/kicad-validation/fabrication/`: front/back copper, front/back solder mask, front paste, front silkscreen, and edge Gerbers; separate PTH/NPTH Excellon files and SVG drill maps; a drill report; a Gerber job file; and a front-side placement CSV. It checks KiCad 10.0.8 file-function headers, metric format and terminators, the edge outline bounds, zero drill counts for this all-SMD fixture, exact BOM-to-placement reference/value/package mapping, and placement coordinates within the board envelope. SHA-256 hashes are recorded in `summary.json` and `fabrication/manifest.json`. This is structural export checking; it does not establish a fabricator's process compatibility or release approval.

## Fail-closed review hardening

The validator now checks the original tscircuit source component, port, net, trace, and probe graph before relying on the converter's SPICE output. This catches source components the converter omits, trace references to unknown identities, and pins moved to a different named net. Source resistance and capacitance are compared numerically across engineering notation and tscircuit-normalized SPICE values.

All configured template, generated-project, and validation paths must stay inside the repository, avoid symlink traversal, and be pairwise disjoint before the validator removes or writes any output. A new run clears the previous success summary, reports, source-build tree, fabrication outputs, and known generated native project files before rebuilding. A failed run therefore cannot leave the prior successful summary in place beside partial new outputs. Generated files are published through temporary files so replacing a hardlinked target does not modify the template. Placement coordinates and rotation must contain non-empty finite values.

The follow-up validation passed all 45 Node integration tests, all 82 Python tests with real ngspice 47 enabled, Ruff, and `pip check`. The fresh KiCad 10.0.8 run reported ERC 0, board DRC 0, unconnected items 0, and schematic/PCB parity 0. These checks strengthen the fixture adapter's failure behavior; they do not broaden it into general-purpose circuit export or establish fabrication release readiness.

This validation establishes a source-directed native KiCad handoff for this simple RC fixture, not arbitrary circuit export. The board has not been fabricated or bench-tested, and a KiCad ERC/DRC pass or structurally checked manufacturing export does not establish manufacturing readiness, assembled component fit, or hardware behavior. Further physical-constraint and fabricator review is required before release. The generated native project is under ignored `build/tscircuit-rc/kicad-generated/`; machine-readable reports, hashes, statistics, preview, and manufacturing outputs are under ignored `build/tscircuit-rc/kicad-validation/`.
